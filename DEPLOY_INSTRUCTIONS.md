# Инструкция по настройке автоматического деплоя

Этот файл содержит инструкции по настройке GitHub Action для автоматического деплоя кода на несколько серверов после мерджа Pull Request.

## 📋 Описание

Workflow `deploy-on-merge.yml` автоматически деплоит код на несколько серверов параллельно когда Pull Request получает статус merged.

## 🔐 Настройка секретов (Secrets)

Для работы деплоя необходимо настроить следующие секреты в настройках репозитория:

### Путь к настройкам:
`Settings` → `Secrets and variables` → `Actions` → `New repository secret`

### Необходимые секреты для SSH/rsync деплоя на несколько серверов:

Workflow настроен для деплоя на 3 сервера: `server1`, `server2`, `server3`.
Для каждого сервера нужно создать отдельный набор секретов:

#### Для server1:
1. **server1_SSH_PRIVATE_KEY** - SSH приватный ключ для доступа к серверу
2. **server1_SERVER_HOST** - IP адрес или домен сервера (пример: `123.45.67.89`)
3. **server1_SERVER_USER** - Имя пользователя для SSH (пример: `deployer`)
4. **server1_DEPLOY_PATH** - Путь на сервере, куда деплоить код (пример: `/var/www/html`)

#### Для server2:
1. **server2_SSH_PRIVATE_KEY** - SSH приватный ключ для доступа к серверу
2. **server2_SERVER_HOST** - IP адрес или домен сервера
3. **server2_SERVER_USER** - Имя пользователя для SSH
4. **server2_DEPLOY_PATH** - Путь на сервере, куда деплоить код

#### Для server3:
1. **server3_SSH_PRIVATE_KEY** - SSH приватный ключ для доступа к серверу
2. **server3_SERVER_HOST** - IP адрес или домен сервера
3. **server3_SERVER_USER** - Имя пользователя для SSH
4. **server3_DEPLOY_PATH** - Путь на сервере, куда деплоить код

### Генерация SSH ключей:

```bash
ssh-keygen -t rsa -b 4096 -C "deploy@github"
```

Публичный ключ нужно добавить на каждый сервер в `~/.ssh/authorized_keys`.

## 🚀 Использование

1. Настройте все необходимые секреты для каждого сервера (см. выше)
2. Создайте Pull Request в ветку `main`
3. После ревью и одобрения смерджите Pull Request
4. Workflow автоматически запустится и задеплоит код на все серверы параллельно
5. Проверьте результат во вкладке `Actions` репозитория

## 🔧 Настройка workflow

### Добавление или удаление серверов:

В файле `.github/workflows/deploy-on-merge.yml` измените список серверов в секции `matrix`:

```yaml
strategy:
  matrix:
    server: [server1, server2, server3, server4]  # Добавьте или удалите сервера
  fail-fast: false
```

После изменения не забудьте добавить соответствующие секреты для новых серверов.

### Изменение целевых веток:

В файле `.github/workflows/deploy-on-merge.yml` измените:

```yaml
on:
  pull_request:
    types: [closed]
    branches:
      - main
      - develop  # Добавьте другие ветки если нужно
```

### Исключение файлов из деплоя:

В секции rsync добавьте `--exclude` для файлов, которые не нужно деплоить:

```yaml
rsync -avz --delete \
  --exclude '.git' \
  --exclude 'node_modules' \
  --exclude 'tests' \
  ...
```

## 📝 Примечания

- Workflow запускается только когда PR **смержен**, а не просто закрыт
- Деплоится код из ветки, **в которую был смержен** PR (обычно `main`)
- Деплой происходит **параллельно на все серверы** одновременно
- Если деплой на один сервер не удался, деплой на остальные серверы продолжится (fail-fast: false)
- При каждом запуске workflow выводит информацию о задеплоенном PR для каждого сервера

## 🔍 Проверка работы

После мерджа PR проверьте:
1. Перейдите в `Actions` вашего репозитория
2. Найдите последний запуск workflow "Deploy on PR Merge"
3. Вы увидите 3 параллельных задачи (по одной для каждого сервера)
4. Проверьте логи выполнения для каждого сервера
5. Убедитесь что файлы появились на всех серверах

## ⚠️ Безопасность

- **Никогда** не коммитьте приватные ключи или пароли в репозиторий
- Используйте только GitHub Secrets для хранения конфиденциальной информации
- Регулярно обновляйте SSH ключи
- Используйте отдельного пользователя с ограниченными правами для деплоя
