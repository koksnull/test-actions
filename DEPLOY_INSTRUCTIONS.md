# Инструкция по настройке автоматического деплоя

Этот файл содержит инструкции по настройке GitHub Action для автоматического деплоя кода на сервер после мерджа Pull Request.

## 📋 Описание

Workflow `deploy-on-merge.yml` автоматически деплоит код на ваш сервер когда Pull Request получает статус merged.

## 🔐 Настройка секретов (Secrets)

Для работы деплоя необходимо настроить следующие секреты в настройках репозитория:

### Путь к настройкам:
`Settings` → `Secrets and variables` → `Actions` → `New repository secret`

### Необходимые секреты для SSH/rsync деплоя:

1. **SSH_PRIVATE_KEY**
   - SSH приватный ключ для доступа к серверу
   - Генерация ключа: `ssh-keygen -t rsa -b 4096 -C "deploy@github"`
   - Публичный ключ нужно добавить на сервер в `~/.ssh/authorized_keys`

2. **SERVER_HOST**
   - IP адрес или домен вашего сервера
   - Пример: `123.45.67.89` или `example.com`

3. **SERVER_USER**
   - Имя пользователя для SSH подключения
   - Пример: `deployer` или `root`

4. **DEPLOY_PATH**
   - Путь на сервере куда деплоить код
   - Пример: `/var/www/html` или `/home/user/app`

### Альтернативные секреты для FTP деплоя:

Если вы хотите использовать FTP вместо SSH, раскомментируйте соответствующий шаг в workflow и настройте эти секреты:

1. **FTP_SERVER** - FTP сервер
2. **FTP_USERNAME** - FTP логин
3. **FTP_PASSWORD** - FTP пароль
4. **FTP_SERVER_DIR** - Директория на FTP сервере

## 🚀 Использование

1. Настройте все необходимые секреты (см. выше)
2. Создайте Pull Request в ветку `main`
3. После ревью и одобрения смерджите Pull Request
4. Workflow автоматически запустится и задеплоит код на сервер
5. Проверьте результат во вкладке `Actions` репозитория

## 🔧 Настройка workflow

### Изменение целевых веток:

В файле `.github/workflows/deploy-on-merge.yml` измените:

```yaml
on:
  pull_request:
    types: [closed]
    branches:
      - main
      - develop  # Добавьте другие ветки если нужно
```

### Исключение файлов из деплоя:

В секции rsync добавьте `--exclude` для файлов которые не нужно деплоить:

```yaml
rsync -avz --delete \
  --exclude '.git' \
  --exclude 'node_modules' \
  --exclude 'tests' \
  ...
```

## 📝 Примечания

- Workflow запускается только когда PR **смержен**, а не просто закрыт
- Деплоится код из ветки, **в которую был смержен** PR (обычно `main`)
- При каждом запуске workflow выводит информацию о задеплоенном PR

## 🔍 Проверка работы

После мерджа PR проверьте:
1. Перейдите в `Actions` вашего репозитория
2. Найдите последний запуск workflow "Deploy on PR Merge"
3. Проверьте логи выполнения
4. Убедитесь что файлы появились на сервере

## ⚠️ Безопасность

- **Никогда** не коммитьте приватные ключи или пароли в репозиторий
- Используйте только GitHub Secrets для хранения конфиденциальной информации
- Регулярно обновляйте SSH ключи
- Используйте отдельного пользователя с ограниченными правами для деплоя
